# Milestone v1.0: Film Clicker MVP

**Status:** ✅ SHIPPED 2026-03-12
**Phases:** 1-3 (Phase 4 skipped — accepted as tech debt)
**Total Plans:** 9

## Overview

Transform the existing YouTube scrubber into a native-feeling film clicker through three focused phases: establish touch-native button foundation, implement core playback and hold-to-scrub controls, and reorganize into film-clicker layout with keyboard shortcuts.

## Phases

### Phase 1: Touch-Native Foundation

**Goal**: Buttons feel like native app controls with instant response, not tappable web text
**Depends on**: Nothing (first phase)
**Plans**: 2 plans

Plans:
- [x] 01-01: Button sizing and touch prevention (44px targets, no text selection, no zoom)
- [x] 01-02: Visual feedback states (press feedback and hold state indicators)

**Details:**
- All buttons have minimum 44px tap targets (py-2.5 minimum)
- `select-none touch-manipulation` on all interactive elements
- Hold buttons use `touch-none` + `e.preventDefault()` for mobile hold gestures
- `active:scale-95 active:bg-*` on all buttons for press feedback
- Per-button `holdDirection` state for distinct held visual state

---

### Phase 2: Core Playback & Scrubbing

**Goal**: Users can play, seek, jump through time, and hold-to-scrub in both directions
**Depends on**: Phase 1
**Plans**: 3 plans

Plans:
- [x] 02-01: Remove step presets, add slow-mo toggle and jump buttons
- [x] 02-02: Replace setInterval scrubbing with RAF-based smooth scrubbing
- [x] 02-03: Human verification of playback and scrubbing functionality

**Details:**
- Slow-mo toggle (default 0.25×) with amber active state replaces speed dropdown
- Fixed-second jump buttons: −1s/+1s, −5s/+5s, −10s/+10s
- RAF time-based scrubbing: `targetTime = startTime ± (elapsed × multiplier)`
- 150ms seek throttle + 5s pre-buffer for smoother mobile rewind
- `scrubSpeedFast` configurable (default 4×), persisted in localStorage and URL

---

### Phase 3: Film Clicker Layout

**Goal**: Controls reorganized into film-clicker style with keyboard shortcuts matching film editing workflows
**Depends on**: Phase 2
**Plans**: 4 plans

Plans:
- [x] 03-01: Reorganize ControlBar into stacked row layout (seek bar → play/toggle → hold → jump)
- [x] 03-02: Add collapsible settings panel with toggle button
- [x] 03-03: Update keyboard shortcuts for film clicker controls (S for slow-mo, modified arrows for jumps)
- [x] 03-04: Human verification of layout, settings panel, and keyboard shortcuts

**Details:**
- Stacked row hierarchy: seek bar → play/toggle → hold (slow) → hold (fast) → jumps → settings
- Mobile: buttons span full width (flex-1), desktop: natural width (sm:flex-none)
- Settings panel collapsed by default, toggle button (▼/▲) at bottom
- Settings: slow-mo speed, scrub speed (slow), fast scrub speed, playback speed
- Keyboard: Space=play/pause, J=rewind, K=play, L=forward, S=slow-mo, Arrow+modifiers=jumps
- `scrubSpeedSlow` added as separate configurable setting (threaded full stack)
- `isSlowMo` persistence bug fixed: derived from loaded settings on init

## Milestone Summary

**Key Decisions:**

- Phase 1: Replace frame-step presets with fixed second jumps (seconds more intuitive for film review)
- Phase 1: Single layout for mobile and desktop (simpler to maintain)
- Phase 1: Per-button holdDirection instead of single isHolding boolean
- Phase 2: Slow-mo toggle instead of speed dropdown (faster to switch during review)
- Phase 2: RAF time-based scrubbing instead of setInterval (eliminates stutter)
- Phase 2: Dual-speed hold scrubbing (slow + fast) — separate buttons over single speed
- Phase 2: seekTo-based scrubbing for all directions (play()-based forward failed on mobile)
- Phase 2: YouTube IFrame API fundamentally limits mobile scrubbing smoothness — accepted limitation
- Phase 3: Stacked row layout over single-row flex-wrap for clearer visual hierarchy
- Phase 3: Settings panel collapsed by default to reduce visual clutter
- Phase 3: S key for slow-mo toggle, arrow keys with modifiers for jumps (progressive modifier pattern)

**Issues Resolved:**

- Slow-mo state persistence bug: `isSlowMo` not persisted across reload (fixed in Phase 3)
- setInterval scrubbing stutter from YouTube API variable latency (fixed in Phase 2 with RAF)
- TypeScript type alignment: `YouTubePlayerController` → `PlayerController`

**Issues Deferred:**

- Phase 4 testing & validation (cross-device QA, network performance testing)
- POLISH-01: Hold delay (300ms) to distinguish tap from hold
- POLISH-02: Haptic feedback on supported devices
- POLISH-03: Seek bar thumbnail preview on hover/drag

**Technical Debt:**

- No automated tests
- Mobile scrubbing smoothness bounded by YouTube IFrame API (accepted limitation)
- Phase 02-03 human verification summary was not created at time of completion
